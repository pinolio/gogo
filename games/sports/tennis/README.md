# 아바타 테니스 (tennis) — v29 (만듦) · v30 (스킬 추가)

선생님 요청(2026-10-29): 오락실 '버추어 테니스 2' 사진처럼 **내 코트가 화면 아래, 상대가 위쪽**인 원근 코트에서 **플레이어 아바타**로 하는 테니스.
(원작의 이름·그림·선수는 쓰지 않고 방식만 참고. 선수는 사이트 아바타가 라켓을 든 모습)

## 방식
| 항목 | 내용 |
|---|---|
| 대결 | AI 대전(쉬움·보통·어려움) · 한 기기 둘이서 · 온라인(다른 기기 친구, 1:1) |
| 코트 | 실제 테니스 코트 크기(m)로 계산, 화면에는 원근으로 그림 (`CAMD`, `CAMH`, `F`, `H0` 를 바꾸면 카메라 위치가 바뀜) |
| 이동 | W A S D 또는 방향키 (휴대폰: 화면 버튼 ◀ ▶ ▲ ▼) |
| 치기 | **스트로크**(J · 스페이스 · F) / **로브**(K · G, 높이 띄워 머리 위로) — 공이 오기 전에 미리 누르면 0.8초 동안 준비, 공이 닿는 거리(약 1.35m)에 오면 알아서 침. 발밑에 노란 고리(로브는 보라)가 준비 표시 |
| 방향 | 칠 때 누르고 있는 방향키: ←→ 좌우 구석, ↑ 깊게, ↓ 짧게. 공을 몸 가까이에서 칠수록 빠르고 정확 |
| 서브 | 스트로크 키 한 번 = 공 올리기, 한 번 더 = 치기. **꼭대기에서 칠수록 빠르고 정확**. 대각선 서비스 박스에 넣어야 함, 폴트 2번 = 더블 폴트. 너무 늦게 치면 다시 올림 |
| 규칙 | 상대 코트(단식 선 안)에 한 번 튀게 넣기. 아웃·네트면 친 사람 실점, 두 번 튀면 받는 사람 실점. 서브는 한 번 튄 뒤에 받기 |
| 점수 | 0 · 15 · 30 · 40 · 게임, 40:40 은 듀스 → AD → 게임. `settings.js` 의 `gamesToWin`(기본 3) 게임을 먼저 따면 승리. 서브는 게임마다 바뀜 |
| 포인트 | 컴퓨터·온라인 승리 +2P / 패배 -1P (한 기기 둘이서는 기록만) |
| 한 기기 2P | 1P(아래): WASD 이동 · F 스트로크 · G 로브 · E 스킬 / 2P(위): 방향키 이동 · 엔터(또는 . · 숫자패드 0) 스트로크 · 오른쪽 Shift(또는 /) 로브 · 오른쪽 Ctrl(또는 ,) 스킬 |

## 스킬 (v30 · 아바타 배구처럼 경기 전에 하나 고름)
선생님 요청(2026-10-29): "테니스 게임도 아바타 배구게임처럼 스킬 몇개 넣어서 선택하게하자"

| 번호 | 이름 | 다시 쓰기 | 효과 |
|---|---|---|---|
| 1 | 순간이동 | 8초 | 공이 내 쪽으로 올 때만 씀. 그 공을 칠 수 있는 가장 빠른 곳으로 순간이동하고 스트로크가 자동 준비됨 |
| 2 | 거대화 | 9초 | 3초 동안 몸이 1.5배로 커지고 라켓이 닿는 거리 1.75배, 높은 공(3.6m까지)도 침 |
| 3 | 불꽃 스매시 | 7초 | 4초 안에 치는 다음 공이 1.4배 빠름(로브 키로 쳐도 스트로크로). 공이 주황빛. 받는 쪽은 방향이 더 빗나감 |
| 4 | 마구 커브 | 7초 | 4초 안에 치는 다음 공이 옆으로 크게 휨(분홍빛). 휘어도 노린 곳에 떨어지게 처음 방향을 반대로 조금 틀어 줌 |
| 5 | 얼음 | 10초 | 상대가 2초 동안 0.4배 빠르기로 움직임(파란빛, '얼음!') |

- **고르기**: 경기 시작 화면에 카드 5장. 숫자 1~5 키 또는 카드를 누름. 한 기기 둘이서는 1P → 2P 차례로, 온라인은 각자 자기 기기에서 고름(먼저 고른 사람은 '다른 사람이 스킬을 고르는 중…'). 컴퓨터는 무작위
- **쓰기 키**: 혼자·AI·온라인 = **E 또는 L** · 한 기기 2P = **오른쪽 Ctrl · 쉼표(,) · 숫자패드 .** · 휴대폰 = 오른쪽 아래 **스킬** 버튼
- **표시**: 선수 이름 밑 막대(다 차면 스킬 색) · 오른쪽 위 내 스킬 상자(한 기기 둘이서는 1P·2P 두 줄) · 쓰면 화면 가운데 '이름 · 스킬!' 과 반짝이
- **숫자 바꾸기**: `settings.js` 의 `skills` — `cd`(다시 쓰기 초), `dur`(효과 초), `power`(불꽃 빠르기 배율), `curve`(커브 세기), `slow`(얼음 빠르기 배율). 카드 설명 `desc` 도 같이 고칠 것
- **컴퓨터 스킬**: `bots` 의 `skill`(쉬움 0.12 · 보통 0.3 · 어려움 0.5) = 쓸 만한 때 쓰는 확률. 순간이동·거대화는 못 갈 것 같은 공일 때, 불꽃·커브는 공이 올 때, 얼음은 공을 보낸 직후
- **온라인**: 고르기는 'pick' → 방장이 모두 고르면 'go'(모든 자리의 스킬)를 보내고 시작. 스킬 쓰기는 손님이 'act'(a: 'skill') 를 보내면 방장이 계산. 상태(0.07초마다)에 스킬 번호·충전·거대화·얼음·준비 상태와 공 효과(fx)를 담아 보냄
- 시험(v30): AI 3단계 승패 정상(쉬움 2:0 승 1분 9초 · 보통 2:0 승 2분 44초 · 어려움 0:2 패 1분 22초, 컴퓨터도 스킬 12번 씀) · 온라인 두 기기 스킬 [3,5] 일치·손님 화면에 효과 보임 · 한 기기 1P·2P 고르기·스킬 키 · 휴대폰 카드 누르기·스킬 버튼 — 모두 문제 0건

## 컴퓨터 (`settings.js` 의 `bots`)
- `run` 달리기 빠르기, `react` 판단 간격(초), `err` 보낼 곳 실수(m), `miss` 못 치는 확률, `out` 크게 빗나갈 확률
- 공이 칠 수 있는 높이(0.25~2.2m)로 내려오는 곳 중 **제때 뛰어갈 수 있는 가장 빠른 곳**으로 달려감. 멀리 뛰어야 하거나 빠른 공(18m/s 이상)이면 더 잘 놓침
- 상대가 없는 쪽 구석으로 치고, 상대가 그물 가까이 오면 로브를 섞음
- 시험(사람처럼 치는 봇, 2게임 경기): 쉬움 1분 25초 2:0 승, 보통 약 3분 2:0 승, 어려움 약 3분 0:2 패

## 온라인
- 방장 기기가 경기를 계산하고 0.07초마다 상태를 보냄. 손님은 방향키 상태와 스트로크·로브 누름만 보냄
- **손님(위쪽 자리)은 화면을 뒤집어** 자기 선수가 아래에 보이게 그림. 조작도 화면 기준으로 맞춤
- 손님이 나가면 그 자리는 컴퓨터가 이어서, 방장이 나가면 경기 끝
